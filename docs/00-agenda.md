เตรียมของฝั่งคนจัด:
- [ ] repo ทดลอง 1 อันที่ทุกคนมีสิทธิ์ write (เช่น `myorg/workshop-playground`) — เอาไว้ให้ทุกคนเปิด PR ชนกันได้

- [ ] `ANTHROPIC_API_KEY` ตั้งเป็น org secret ไว้แล้ว (ถ้าจะสาธิต [06](06-claude-on-github.md))

## วิธีคุมแต่ละช่วง

**ช่วง 0:00 — ปัญหาจริง**
ให้แต่ละคนเล่าเหตุการณ์ล่าสุดที่ "แก้แล้วพัง" หรือ "รีวิวไม่ทัน" เขียนขึ้นกระดานไว้
ตอนจบ workshop กลับมาชี้ทีละข้อว่าข้อไหนถูกแก้ด้วยอะไร — นี่คือสิ่งที่ทำให้คนเชื่อว่ามันคุ้ม

**ช่วง 02 — Claude Code**
อย่าบรรยายฟีเจอร์ ให้ทำสด: เปิด repo จริง สั่งงานหนึ่งอย่างแบบ**ไม่มี** `CLAUDE.md` ให้เห็นว่ามันเดาผิดตรงไหน
แล้วเขียน `CLAUDE.md` ใส่ สั่งซ้ำ ให้เห็นความต่าง — จุดนี้คือหัวใจของทั้ง workshop

**ช่วง 03 — PR**
จับคู่ ให้ A เปิด PR ใน playground แล้ว B เป็นคนรีวิว สลับกัน
บังคับให้มีอย่างน้อย 1 comment ที่ "ขอให้แก้" จริง ๆ ไม่ใช่ approve รวด

**ช่วง 04 — CI**
ทำกับ playground ก่อน แล้วให้แต่ละคนลองไป apply กับ repo ตัวเอง 1 อันในห้อง
คนที่ไม่มีสิทธิ์ admin ให้จดชื่อ repo ไว้ ไปคุยกับ org admin หลังงาน

**ช่วง 05 — Multi-repo**
รัน `./scripts/audit-repos.sh <org>` สดหน้าห้อง ให้ทุกคนเห็นตารางว่า repo ไหนยังโล่ง
ตารางนี้แหละกลายเป็น backlog ของช่วง 3:40
